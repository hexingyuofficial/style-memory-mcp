# style-memory-mcp v0.5.0 详细执行计划

> 本计划是 [`V0.5.0-HARDENING-PLAN.zh-CN.md`](V0.5.0-HARDENING-PLAN.zh-CN.md)
> 的实施顺序。加固计划是验收真源；如有冲突，不得自行改弱验收条件。

## 1. 执行角色

- **主 agent**：使用 `gpt-5.6-luna`、`xhigh` reasoning。主 agent 是唯一集成负责人，
  必须亲自阅读契约、设计测试、审查全部 diff、运行验收、维护状态和完成交付；不能把整个版本转交给 subagent。
- **低等级 worker（可选）**：最多创建一个 `gpt-5.6-luna`、`medium` reasoning worker，并在 S1-S8 间复用；
  同一时间最多一个 worker 活跃。只接收边界明确的小任务，例如整理一个 fixture、实现一个独立 helper、
  排查一个失败测试或做一次只读核对。worker 不得再拉 subagent、修改计划状态、执行安装/发布/Git 提交，
  也不得与主 agent 同时修改同一文件。主 agent 必须逐行检查其改动并亲自验证。
- **最终 reviewer**：全部本地验收翻绿后只创建一个最高等级 `gpt-5.6-sol` reviewer，
  使用环境允许的最高 reasoning effort。reviewer 只读审计，不编辑文件；必须独立阅读契约、完整 diff、
  测试和实验证据。后续复查复用同一个 reviewer，不重复创建 reviewer。

如果指定模型或 reasoning effort 在当前环境不可用，主 agent 必须记录真实可用模型，不能假称已使用。
最终 `gpt-5.6-sol` reviewer 不可用时，不得将终审门槛标绿或把 Goal 标记完成；应保留现场并明确报告阻塞。

## 2. 强制工作流

实施窗口启动后，主 agent 先创建一个持久 Goal，目标必须明确写成：完成 S1-S8、SM-050-01 至
SM-050-10、E01-E10、全量命令和最终 Sol review，全部翻绿且无遗留问题；不 commit、不发布、
不修改真实安装。Goal 在整个实施期间保持 active。

S1-S8 每个阶段执行下列本地循环：

1. 主 agent 只把当前阶段设为进行中，列出该阶段将修改的文件、不可变边界、失败测试和验证命令。
2. 先补能在旧行为上失败的 fixture/断言，确认失败原因与契约一致，再实现最小完整修复。
3. 若使用 worker，只派发一个文件边界清楚、可以独立验收的子任务；收到结果后立即复核，
   不允许 worker 的摘要替代源码检查。
4. 主 agent 亲自检查当前阶段全部 diff，运行定向测试、`npm run check` 和 `git diff --check`；
   涉及共享 store、协议、迁移或安装时同时运行全量 `npm test` 和 `npm run build`。
5. 任一断言失败、边界未覆盖或证据不可复现，当前阶段保持 `⬜`，继续修复并重复步骤 2-4。
6. 只有实现、定向实验、回归命令和阶段证据均通过，才能把该阶段及对应 SM/E 项逐项标为 `🟩`。
7. 一次只允许一个阶段处于实施中，不在多个共享文件上并发写入，不在最后整批翻绿。

S1-S8 和所有 SM/E 项本地翻绿后，执行最终审查循环：

1. 主 agent 再跑一次全部最终命令，检查 status、完整 diff、迁移/安装隔离边界和证据索引。
2. 只创建一个最高等级 `gpt-5.6-sol` reviewer，明确要求只读、按严重度列 findings，
   并逐项核对加固计划、E01-E10、回归测试、token 数据和未提交边界。
3. reviewer 只要有一个未解决 finding，立即把受影响的 S/SM/E 项退回 `⬜`；主 agent 修复后重跑
   受影响实验和最终命令，再向同一个 reviewer 发送 follow-up 请求复查完整修复。
4. 重复步骤 2-3，直到同一个 reviewer 明确返回无遗留 findings，所有退回项重新为 `🟩`。
5. 只有此时才记录终审证据、把最终审查门槛标绿，并将 Goal 标记 complete；随后停在未提交状态。

不得通过删除测试、改弱断言、跳过 fixture、扩大超时或把失败用例标成 skip 来翻绿。

## 4. 分阶段执行

### S1 契约与失败测试

目标：先把已确认的语义变成 TypeScript 契约和失败测试，不先写大量实现。

必须完成：

- 定义合法方向只有 `user→assistant` 与 `assistant→user` 的称呼类型；`AddressValue` 至少含独立 id、
  text、usageSummary、affectSummary、useWhen、status、confidence、pinned/explicit。相同 literal 在两个方向
  必须能并存，任何单方向管理操作不得串改另一个方向。
- 定义称呼容量：store 每方向最多 6 个，brief 每方向最多 2 个且典型为 1 个；满容量时拒绝自动候选，
  不允许通过静默淘汰规避上限。称呼不参加表达模式 TTL 自动遗忘。
- 定义量表、`ExpressionPattern`、受控变体策略、特殊标点和翻车规则的类型；表达行为/功能是主记录，
  具体原文只能放在 `examples` 和证据中。
- 定义表达模式容量和 TTL 契约：brief 典型 2/最多 5，store 未固定 active/candidate/archived 为
  12/24/24、总安全上限 64，TTL 为 30/180/360 天，pinned 受保护。
- 定义 `observedVoice` 与 `responsePreferences` 的不可交叉契约。
- 定义六段 brief 的 golden fixture，包含空段、最大项数、数值标签、两个称呼方向、同 literal 双向碰撞、
  `用户→助手[只识别，勿反称]`、短情绪/关系摘要和 `助手→用户[可以使用]`。
- 定义紧凑的语义 hint、独立 `sessionId` 和新 session bootstrap 契约；最终分数不能由 hint 直写。
- 定义 hook/agent 两种观察通道，`full/event/off` 学习策略、runtime/admin 工具面、
  brief revision/delta 和 20 回合总 token 计量契约。
- 为 `E01-E06` 添加会在旧代码上失败的测试，记录预期失败原因。
- 不把文档中的表达模式或原文示例预填进默认 store。

阶段验证：

```bash
npm run check
npm test
git diff --check
```

主 agent 自验/最终 reviewer 必查：称呼是否仍是无方向字符串；`affectSummary` 是否被误作心理诊断；
同 literal 双向操作是否串改；类型是否将用户语感和 agent 回应偏好混在一起；是否仍以单个 literal
充当完整风格；是否有从文档示例自动学习的路径；旧 API 兼容边界是否写清。

### S2 store v2 与迁移

目标：使现有 `version: 1` store 无损升级到 `version: 2`。

必须完成：

- 新 store 默认值和严格运行时校验。
- 显式 `migrateV1ToV2`，不在多个 normalize 分支中隐式改形。
- v1 中没有可靠方向证据的称呼/昵称不得猜成 `助手→用户` 并直接 active；必须保留原数据到可审计的
  兼容候选/迁移报告，等待用户确认方向。迁移不得凭 literal 编造 `affectSummary`。
- 旧 habit 的 id、text、confidence、seenCount、status、pin、example、contexts 和时间都保留为
  v2 模式的兼容来源/例子；迁移不得凭 literal 编造细微的行为功能。
- 旧 `emoji` 根据原文可安全区分时迁移为 `emoji/kaomoji` 例子，不可确定时保留为兼容类型而不丢数据；
  语义不足的旧项保持 candidate 或 `exact_only`，等待新证据确认后再扩大变体范围。
- 特殊标点保持 literal。
- 迁移不得因 v2 新容量删除旧数据；允许迁移后暂时超限，由首次正常 cleanup 返回可审计计数。
- 使用临时文件 + fsync + atomic rename 替换 store，迁移前创建唯一备份。
- 重复加载 v2 不再迁移，重复运行安装不重复生成备份风暴。

阶段验证：`E08` 全部 fixture + 全量基线测试。

主 agent 自验/最终 reviewer 必查：迁移失败是否可能截断原 store；旧称呼是否被猜错方向；
未知字段策略是否一致；迁移是否幂等。

### S3 观察与分类

目标：让正常聊天能自动生成正确类型的候选证据。

必须完成：

- 称呼观察和 hint 必须包含合法 `from/to`，并绑定当前用户消息；无方向、非法方向或来源为 assistant
  输出的证据必须拒绝。默认不将用户对 agent 的称呼反向渲染。
- 用户→助手可以保存多个候选；自动激活沿用至少 3 次实际直接呼语、跨 2 个 session 的门槛。
  明确要求/确认可立即激活。每个 active 项必须有一句短的可观察情绪/关系语境；
  证据不足时使用中性摘要，不猜心理。
- 助手→用户称呼只在用户明确要求/确认，或多次无歧义表达“你可以这样叫我”后激活；
  assistant 自己使用昵称不能创建、计数或提高 confidence，避免自我强化。
- 引用、转述、否定、反例、第三方姓名、角色名、文档示例、环境文本和工具输出不得进入称呼 store。
- 同 literal 双向并存时，观察、confirm、correct、forget、archive 和 pin 全部按 `direction + id` 定位；
  “这是我叫你的”只纠正用户→助手方向，除非用户同时明确要求删除另一方向。
- 称呼和摘要输入分别限长、脱敏；只保存短摘要和必要证据，不保存整段对话。
- 规则提取 emoji、颜文字和特殊标点原文作为低层例子证据；不从单个字符直接推断完整行为模式。
- 宿主 hint 支持紧凑的 `kind + behaviorSummary + functions + variationPolicy`，服务端限长、脱敏，
  不接受对用户的心理/性格标签。
- 同一模式的活跃门槛为至少 3 次实际观察、2 个会话；不同 literal 只有在 kind/function 匹配时
  才能合并计数，会话 ID 不能用场景 label 冒充。
- 宿主观察输入保持短小，不传整段聊天记录。
- hook 通道由宿主在模型外逐消息观察；agent 通道冷启动需要精确统计时使用 `full` 逐消息提交，
  核心记忆成熟后使用 `event`，只在明确偏好、纠正、明显表达模式或新例子实际出现时提交。
- 同一 session 的观察使用同一个无语义短 ID，不同 session 可区分；优先由宿主集成层自动提供。
- 未提交的消息不补算；session 末蒸馏候选最多贡献 1 次低权重观察，不接受批量 count，
  不绕过表达模式 3 次、2 个 session 门槛。
- bootstrap/status 返回 channel、policy 和核心记忆成熟度；状态接口明确报告学习速度与 token 代价。

阶段验证：`E01-E04`、敏感信息测试和现有 extractor 回归。

主 agent 自验/最终 reviewer 必查：方向混淆；双向同 literal 串改；assistant 输出自我强化；
情绪摘要越界成心理诊断；把引用、他人称呼或环境上下文当用户称呼；对 Unicode 做损失归一化；
把一次性字符当完整模式；把不同功能的颜文字错误合并；让模型从一个例子无限制扩展。

### S4 量表证据引擎

目标：实现稳定、可解释、不抖动的 `1-5` 和 `0-3` 量表更新。

必须完成：

- 证据记录包含 field、observedValue/delta、source、weight、sessionId、timestamp 和可选 reason。
- 最近 50 条有效证据的有界滚动窗口。
- 截尾或加权中位数、滞回、最小证据数和跨会话门槛。
- 明确绝对要求、方向性反馈和普通观察分开处理。
- pinned/explicit 值不被低权重观察覆盖。
- 不把“未出现某表达模式”当作每轮反证。
- 内部 confidence 的更新和对外 value 的更新分开。
- 参数放在集中配置或算法常量中，不散落在多个分支。

阶段验证：`E05` 全量数据集，并输出每个场景的变化轨迹供 review。

主 agent 自验/最终 reviewer 必查：单条离群值；频繁 2/3 来回抖动；用户固定值被冲掉；
将用户表达长度错当成回复长度偏好。

### S5 brief 与纠错

目标：产生小 token、可直接执行的六段风格记忆，并使用户纠错在同轮生效。

必须完成：

- 渲染器固定标题顺序，空段省略，量表值附固定中文语义。
- 表达项渲染为“行为/功能 + 一个代表例子 + 变体边界”，不渲染 literal 清单，不注入内部 confidence。
- 口癖、标点和表情统一从 `ExpressionPattern` 选择，同一模式不跨段重复；
  典型 brief 选择 2 个表达模式，硬上限 5 个，capsule token 上限具有更高优先级。
- 默认只渲染最高价值 active 项；默认值、低 confidence、重复或当前无关项省略，
  当前情境变化时重新选择相关模式，不能长期固定霸占同一组。
- 称呼按两个独立方向渲染；用户→助手行固定显示“只识别，勿反称”并带一句短情绪/关系或中性摘要，
  助手→用户行固定显示“可以使用”和短使用条件。相同 literal 双向存在时不得合并行或丢方向。
- 只渲染 active/explicit/pinned 称呼；每方向典型 1 个、最多 2 个。用户→助手项不得进入可调用称呼列表，
  生成侧只能从助手→用户项选择。
- 实现翻车日志的 add/list/forget/pin 或等价管理路径。
- 用户明确纠错的消息优先执行纠错，并跳过同轮对被禁项的观察。
- 保持现有结构化 brief API，为旧客户端提供明确兼容层或迁移错误，不静默改语义。
- brief 带 revision；未变化时不重复正文，普通变化返回 <=30 token delta，必要时才返回完整 capsule。
- runtime 工具不超过 3 个，日常 observe/sync 只返回紧凑 ack/refresh；完整对象和管理操作移入 admin 工具面。

阶段验证：`E03`、`E06`、`E07`，外加现有 brief/review/forget/pin 回归。

主 agent 自验/最终 reviewer 必查：裸 `3/5`；文档示例被注入；称呼方向标签或情绪摘要被省略；
同 literal 双向项被错误合并；用户→助手称呼被反用；只有原文没有行为/功能；超过 5 个模式或为凑满
5 个突破 token 上限；`same_family` 被机械照抄或无限扩展；`exact_only` 被改写；空段浪费 token；
用短 brief 掩盖庞大 schema、工具返回或额外模型往返。

### S6 存储与安全

目标：新增数据结构不降低现有存储和隐私安全。

必须完成：

- 所有新字段都有长度、数量、枚举/范围和敏感信息校验。
- 称呼严格执行每方向 6 个的 store 上限和每方向 2 个的 brief 上限；并发新增不能越界，
  满容量自动候选返回可解释拒绝，不能淘汰另一方向或把称呼交给表达模式 TTL cleanup。
- 并发观察、明确反馈和迁移不丢更新，不破坏 store。
- 损坏文件恢复不静默覆盖唯一副本；保留可调试备份且不泄露内容到日志。
- 新增会话 ID 只是无语义标识，不存会话标题、对话全文或个人身份。
- 证据窗口有硬上限；实现 30/180/360 天的 candidate 删除、active 归档、archived 删除。
- 实现未固定 active/candidate/archived 的 12/24/24 容量和 64 总安全上限；超限按
  `pinned > explicit > sessionCount > seenCount > lastSeenAt > stableId` 确定性处理。
- pinned 不被自动遗忘；全 protected 达到安全上限时拒绝新自动候选并报告容量状态。
- archived 重新出现后只以归档后的新证据重走 3 次、2 session 门槛；明确用户确认可立即恢复。
- 自动遗忘只作用于表达模式，不作用于称呼、明确陪伴偏好和翻车日志。

阶段验证：`E09` + 并发压测 + 现有 sensitivity/store/cleanup 回归。

主 agent 自验/最终 reviewer 必查：无界数组；称呼双向并发时越过单方向容量或串改；TTL 边界差一天；
容量排序不稳定；误删 pinned；旧累计证据让 archived 一次出现就复活；自动遗忘称呼/翻车日志；
敏感文本落盘；竞态丢更新；损坏恢复把原件覆盖。

### S7 安装升级与回滚

目标：安装给已有 agent 时自动替换旧程序，但任意失败都不会将用户留在半安装状态。

必须完成：

- 版本化 runtime 目录和稳定 launcher。
- 可重入的 `install-or-upgrade` 入口，明确区分 staging、active 和 backup。
- 安装锁和 stale-lock 安全处理。
- 构建/测试通过后才进行迁移，迁移通过后才切换。
- 可发现旧的 repo-path、npm global 或已配置 launcher 安装；不能猜测不受支持的宿主配置并盲目改写。
- 修改任何宿主配置前备份，使用结构化 JSON 解析，不做字符串替换。
- `get_style_memory_status` 返回 serverVersion、storeVersion、runtimePath，作为切换后握手。
- 将稳定 launcher 写入受支持宿主的持久 MCP 配置，并将短启动协议写入其全局 agent instruction；两者修改前都备份。
- 新建独立 session 演练：无需手动启动进程，首轮读取同一绝对 store，并在回复前获得 brief。
- 探测宿主是否支持模型外消息 hook：支持时安装逐消息自动观察；不支持时安装按
  `full/event/off` 执行的短指令，不得用“每轮模型工具调用”冒充零成本 hook。
- 默认聊天配置只启用 runtime 工具面；admin 工具面独立配置或按需启用，避免全部 schema 常驻。
- 实现 fault injection 开关，覆盖 `E10` 的每个故障点。
- 安装成功和回滚都输出机器可读结果，便于宿主和测试判断。

阶段验证：从真实 `v0.4.0` fixture 执行 `E10`，不只测试全新安装。

主 agent 自验/最终 reviewer 必查：先覆盖再备份；迁移直接写原 store；切换非原子；并发安装竞态；
只校验文件存在而不做运行时握手；安装器未经用户配置就扫描并修改不相关配置。

### S8 文档、全量回归与交付

目标：用新用户、旧 store 用户和已安装 v0.4.0 用户三条真实路径证明可以交付。

必须完成：

- 更新 README、中文用户指南、接入指南、agent instruction、CHANGELOG 和安装说明。
- 文档显示六段最终格式，口癖以表达行为为主、具体字符仅作例子，并说明三种受控变体策略；
  所有格式例子明确标注不是用户事实。
- 文档说明双向称呼的 from/to、用户→助手短情绪/关系摘要、只识别不反称、助手→用户的启用条件、
  每方向容量，以及单方向纠错不影响另一方向。
- 说明 brief 只在开局和 revision 变化时注入；hook 通道逐消息观察，agent 通道按
  `full/event/off` 学习，两者能力和 token 代价不同。
- 说明普通使用中哪些字段会自动形成，哪些需要明确反馈。
- 说明表达模式“store 最多记多少、brief 每次给多少”和 30/180/360 天简单遗忘；
  明确 pinned、主动 forget、重新激活以及哪些记忆绝不按未出现自动遗忘。
- 说明跨 session 需要“持久 MCP 配置 + 固定 store 路径 + 全局 agent 指令”，MCP 不能自行向未调用它的上下文推送 brief。

  包括 capsule 在后续模型输入中的实际占用；缓存 token 单列，不当作零成本，
  并证明最终选择是在稳定性达标方案中成本最低者。
- 对比“多个孤立 literal”与“一个行为模式 + 一个例子”，证明后者能使用未见过的同类颜文字、
  不机械复读、不漂移到无关风格；只在行为均达标的方案之间比较总 token。
- 为 `E01-E10` 生成证据索引：命令、fixture、断言和实际结果。
- 将加固计划与本执行计划所有项逐一翻绿，不整批修改状态。
