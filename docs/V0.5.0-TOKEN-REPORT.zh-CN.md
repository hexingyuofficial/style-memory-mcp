# v0.5.0 E06 Token 报告

日期：2026-08-02。本文是测量边界报告，不把字符串长度冒充模型 token，也不声称完成真实 20 回合成本测量。

## 协议覆盖范围

本地可复现的结构断言位于 `src/v2.test.ts`：

- 首次 `bootstrap_style_memory` 返回 `channel`、`policy`、`revision` 和 capsule；
- 已知 revision 未变化时只返回 ack；
- revision 过期时返回 delta，且不重复完整 brief；
- capsule 按六段顺序渲染，空段可省略；
- 典型 brief 的称呼方向和表达模式数量受限，表达模式通常选 2 项；
- 默认 runtime tool 面只有 bootstrap、observe event 和 get brief，admin schema 不进入默认连接。

这些断言证明协议能支持低重复注入，但不提供模型 token 数。

## 必须计入的成本

一次固定 20 回合对话的实际报告必须分别记录：

1. 持久 agent instruction；
2. 每轮实际暴露的工具 schema；
3. 每轮工具调用参数和工具返回；
4. 首次 capsule；
5. 每次 delta 或 ack；
6. capsule 留在后续模型输入中的重复占用；
7. 每轮模型 input/output usage；
8. cached input，单独列出，不能当作零成本。

应比较完整六段、active-only 紧凑六段和 capsule+delta，并在称呼方向、明确偏好、口癖自然性和跨 session 稳定性均达标的方案中选择总成本最低者。
还应比较 `hook+full`、`agent+full`、`agent+event` 和 `off` 的模型调用轮次。

## 当前环境限制

当前仓库环境没有目标模型 tokenizer，也没有真实模型 API usage/cached-input 数据。MCP 是本地规则服务，不能自行生成这些 usage；
`npm test`、TypeScript 检查和 brief 字符计数都不能替代 tokenizer。因而本报告不输出伪造的 token 数、不把字符数乘常数作为结果，
也不声称 E06 的真实 20 回合成本门槛已经测量完成。

可复现的本地验证命令仍是：

```bash
node --import tsx --test src/v2.test.ts
npm test
npm run check
npm run build
git diff --check
```

实际本地结果：v2 定向协议断言通过，完整 suite `132/132` 通过，check/build/diff check 退出码为 0；这些结果只证明实现和协议结构，
不改变上述模型 token 限制。

## 交付解释

在没有目标 tokenizer/API usage 的环境中，E06 应标记为“结构协议通过、真实 token measurement 未执行”。任何把 brief 字符数写成 token、
把 cached input 写成零成本、或把“只注入一次”写成“只支付一次”的报告都不符合 v0.5.0 契约。
